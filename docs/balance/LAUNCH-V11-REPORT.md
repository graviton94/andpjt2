### 운영 코어 수식

- 회차 레벨의 기준 P는 `Q₂=30`, `r_L=2.330+0.001×max(L−24, 0)`이다. `Q_{L+1}=Q_L×r_L×m_L`이며 Lv74에서 Lv75로 갈 때부터 `m_L=0.86`을 곱한다. 그 전까지는 1이다. 표에 제공하는 누적 P는 소수부를 버린 정수다. 빠른 부팅 단계마다 필요 P에 0.9를 곱한 뒤 정수 경계에서 레벨을 계산한다. Lv124 기준 P는 같은 기본 곡선의 약 `0.86^50 = 0.000531`배다.
- GB는 주기 백업파일을 Lv60 회차 백업파일로 나눈 값에 제곱근을 취해 10을 곱하고, 기준 최고 주기의 지급 누계를 뺀다. 속도 패스의 환생 배율은 쓸 수 있는 GB에 적용한다. 진입 조건은 Lv75다.
- 오프라인 분당 수입 창은 180스와이프다. 기본 효율 9%에 백업의 오프라인 보너스 단계당 2%p를 더하고 직접 수입 대비 자동 기준 40%, 인정 분과 광고·패스 배율을 곱한 뒤 게임의 레벨 상한을 적용한다. 인정 시간과 화면 금액 필드의 단위는 기존 계약을 따른다.

콘텐츠 배치는 배다른민족을 Lv31→25, 쿠빵을 Lv43→72로 옮겼다. 6티어 앱 여섯 개의 진입은 Lv72·74·76·78·80·82다. 7티어는 Lv73~78, 8티어는 Lv74~79로 엇갈려 배치했다. 해당 앱의 프로는 기본 앱 해금보다 25레벨 뒤다. 기존 저장이 `rulesVersion ≤ 4`이면 업데이트 시점까지 연 앱을 보존한다. 공장 초기화와 동기화 후에도 이어지며 SaveCodec 외피는 버전 1이다. 오프라인 몫은 각 시드의 실제 지급 `오프라인 P / (활성 P + 오프라인 P)`를 집계한다. 당일 복귀 광고 즉시 지급은 오프라인에, 최고 기록 광고와 시간 도약은 활성에 넣는다. 목표 30~50%는 v1.0과 같은 무과금 최선조작 기준이다. 패스와 속도 구독의 오프라인 몫은 별도로 공개한다.

## 4. 큰 연쇄의 실제 경로와 제안

스와이프가 비운 자리에 합칠 수 있는 두 줄이 닿으면 직접 폭발한다. 이어서 만나는 다음 쌍마다 두 줄을 더 소모한다. 네 번 직접 폭발하려면 최초 민 한 줄 외에 여덟 줄과 네 쌍이 필요하다. 파동은 같은 스와이프에서 보드의 줄을 추가 소비하지 않으면서 표시 연쇄를 올린다. 튄더의 두 줄은 전용 보너스 +2를 붙일 수 있으므로 별도 경로로 분류했다.

`chain-paths.csv`에는 직접 폭발 횟수, 튄더 합체 가산, 파동 횟수와 최종 표시 연쇄가 있다. 분해가 맞는지 스크립트가 검사한다. 색 등급별 경로는 해당 등급 하한을 넘긴 단계로 정했다. 예를 들어 물리 3연쇄에 파동으로 9연쇄가 된 건 파동이 만든 9+다.

| Free/Best | 일자 | 스와이프 비율 중앙값 (최소~최대) | 하루 출현 중앙값 | 폭발 / 합체 / 파동 횟수 합계 |
|---|---|---:|---:|---:|
| 2–3 | 1~14일 | 34.46% (32.59~36.53%) | 516.96 | 58,478 / 0 / 122 |
| 4–5 | 1~14일 | 0.85% (0.82~0.98%) | 12.96 | 799 / 0 / 682 |
| 6–8 | 1~14일 | 0.08% (0.07~0.13%) | 1.25 | 0 / 0 / 158 |
| 9+ | 1~14일 | 0.20% (0.18~0.25%) | 3.07 | 0 / 0 / 359 |
| 물리 3+ | 1~14일 | 4.88% (4.64~5.33%) | 73.21 | — |
| 물리 4+ | 1~14일 | 0.47% (0.43~0.57%) | 7.21 | — |
| 2–3 | 15~84일 | 33.09% (32.42~36.13%) | 613.04 | 348,727 / 527 / 18 |
| 4–5 | 15~84일 | 0.58% (0.49~0.86%) | 10.80 | 5,899 / 289 / 157 |
| 6–8 | 15~84일 | 0.02% (0.02~0.04%) | 0.31 | 0 / 22 / 182 |
| 9+ | 15~84일 | 0.61% (0.61~0.62%) | 11.34 | 0 / 1 / 6,359 |
| 물리 3+ | 15~84일 | 3.45% (3.03~3.69%) | 63.91 | — |

초반에는 물리 3연쇄 이상이 4.88%, 후반에는 3.45%다. 9+ 표시 6,719회 중 6,718회가 파동 경로였고 1회는 튄더 합체 가산 경로였다. 화면의 4+만 합산해 목표로 두면 손으로 만든 폭발과 파동이 같은 숫자로 섞인다.

- **권장안** · 직접 폭발 3번 이상을 1~14일 **4% 이상**, 15일 이후 **3% 이상**으로 잡는다. 15일 이후 표시 9+는 4회×15분 기준 **하루 8회 이상**으로 판정한다. 폭발률과 과부하 횟수의 기존 조건도 함께 본다.
- **비교안** · 기존 4+ 색 연출을 기준으로 삼을 경우 표시 4~5 구간 **하루 8회 이상**을 기록하고, 큰 연출은 별도 **9+ 하루 8회 이상**으로 본다. 출시 전에 4+ 8~15%를 고정하려면 보드 또는 파동 빈도의 별도 검증이 필요하다.

## 6. 검증과 남은 결정

- 코어 90개 테스트 통과. 새 BM의 30일 환산, Lv75 직전의 동기화 차단, Lv60 GB 기준, 이전 앱 해금의 초기화·동기화 보존을 확인했다. 운영 기본값과 후보 규칙의 광고 시드 1·30일에서 시드·광고·연쇄·해금 공백 CSV가 각각 바이트 단위로 일치했다.
- Chromium에서 월간 캡슐과 세 패스 아래 가치표, 스타터·초심자, Play ID 11개를 확인했다. 15시간 복귀는 12시간 인정과 초과 3시간 문구, 패스 +70%와 실제 P, 제안 재전송 차단을 검증했다. [복귀 증거](launch-v11-data/return-15h.json) · [패스 증거](launch-v11-data/pass-values.json)
- 게임 페이지 생성기는 한국어 문구 길이와 번역 키를 통과했다. 앱에 포함된 HTML은 v1.0 효과 원본에서 바뀐 앱 15개의 이전 한국어를 담고 있다. 패스 가치 표시는 두 빌드에서 재현됐고, 앱 효과 문구는 화면 트랙에서 소스로 다시 생성하면 일치한다. [원본과 패키지 문구 차이](launch-v11-data/korean-effect-asset-drift.tsv)
- Android 로컬 조립·lint는 `com.kakao.sdk:v2-user:2.21.4` POM의 HTTP 403으로 중단됐다. GitHub Actions 조회도 이 환경에서 HTTP 403을 반환해 기기 합격은 미확인이다. 실제 AdMob 복귀 경로와 실앱의 스크린샷은 Android 트랙에서 검증해야 한다.
- 큰 수입 손실은 출시의 별도 위험이다. 무과금 스와이프의 과열 발생은 0.50%지만 정산 후보 P 중 잘린 몫은 15.98%, 최악 시드에서 52.26%였다. Lv74 이후 레벨 간격이 좁아지면서 같은 +3레벨 제한이 더 적은 P를 인정한다. 자동 정리가 수동보다 한 주 앞선 경우도 시드 5의 10주 차 1/96쌍 있다. 자동이나 파동의 보상을 더 키우기 전에 이 손실의 발생 구간을 먼저 봐야 한다.
- 이번 판정에서 추가 승인이 필요한 것은 연쇄 목표다. §4의 권장안은 실제로 여러 쌍을 터뜨린 빈도와 과부하 파동 연출을 따로 측정한다. 기존 4+ 목표는 승인 전까지 판정표에 유지한다.
