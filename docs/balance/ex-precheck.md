# 유료 EX 구현 착수 전 검증

## 판정

**착수 기준 미달.** 30개 시드 × 6개 프로필 × 8개 보유·대안 구성의 **1,440개 실행**을 제출한다. A 효과 크기와 B 부분 보유 단조성이 미달했다. C 조건 측정과 E 재현 자료는 완료했다. D 진행 단축은 비교한 터보보다 작았으며, 오프라인 대안도 착수 기준에 미달했다. 현재는 조건부 승인에 따른 증거 검토 단계다.

사용자가 확정한 사항은 9 SKU·개당 ₩3,300, 보유당 상시 +0.50%p, 완성 세트당 +0.75%p, 전체 완성 +1.00%p, 최대 +10%, 보유권의 환생 간 유지, 고정 시드 도전에서 EX 가산 제외, 기존 레벨 상한을 적용한 실제 추가 P 산식이다. 각 아이템의 조건부 +0.25%p는 검토 대상으로 남아 있다. [이전 검토 자료](ex-review-report.md)

## A. 효과 크기와 환생 판단

시드 1–30, 84일 한도, 하루 4세션 × 15분이다. 기존 플레이어가 선택하는 수동 스와이프와 기본 환생 판단을 사용했다. 각 케이스는 56일차 마지막 세션까지, Lv124를 아직 통과하지 못한 케이스는 첫 도달 또는 84일까지 실행한다. 기본 보상 정책 5개와 `OfflineDouble` 지면을 제외한 화면 보상 월간 패스를 각각 집계한다.

7·14·28·56일차 시점은 각 날짜 마지막 세션과 환생 판단 직후다. 시점 레벨은 현재 회차 기준이며 최고 기록도 별도 열로 보존했다. 회차 P가 0일 때는 `log10(max(1, P)) = 0`이다. 누적 백업파일과 GB는 각 지급 직후의 잔액 차이를 평생 합산했다. 유료 속도 구독이 GB에 추가한 지급량은 누적 지급 GB에 포함했다.

각 시점 차이는 동일 시드의 EX 값에서 미보유 값을 뺀다. 도달일 차이만 미보유 일수에서 EX 일수를 빼 양수가 빠른 값으로 표시한다. 84일 미도달은 사건 상태를 별도로 표시하고, 도달 시각 대신 84를 넣은 제한 일수 차이를 계산한다. 양쪽이 실제로 도달한 짝의 평균도 별도로 낸다. 양쪽 미도달은 개별 지연을 확정할 수 없다. 평균과 중앙값의 95% 구간은 같은 시드 차이를 통째로 재표집한 백분위 부트스트랩 4,000회다. 울트라·터보의 5% 기준은 해당 프로필 미보유 84일 제한 평균에 적용했다.

독립 재실행에서도 미보유 **54.00일**, 풀세트 **66.00일**이었다. 최초 리셋은 양쪽 1.01일 Lv26이다. 두 번째 리셋은 풀세트에서 2.01일 Lv29, 미보유에서 3.01일 Lv31이다. 첫 도달 직전 미보유는 51.01일 Lv121 동기화 후 53.01일 Lv122 초기화를 거쳐 54일에 Lv124를 넘었다. 풀세트는 53.18일 Lv115, 55.51일 Lv117, 59.01일 Lv121에서 동기화했다. 이어 62.01일 Lv123에서 초기화하고 63.34일 Lv123에서 동기화해 회차 P가 다시 시작됐다.

## B. 부분 보유와 순차 구매

0개, 프리즘 궤적 1개, 각 세트에서 1개씩 3개, 프리즘 1세트, 프리즘·리부트 2세트, 전체 9개를 동일한 30개 시드로 비교한다. 분산 3개는 `prism_trail,reboot_frame,studio_deck`이다. 같은 수량에서 분산 구매와 완성 세트를 별도 대조한다. 순차 구매는 3일차와 14일차의 첫 세션 시작 7분 30초 후 각각 프리즘 세트와 전량을 기준으로 적용했다.

일반 정산에서 같은 상태의 구매 효용은 기존 레벨 상한·내림을 적용하기 전마다 수치상 증가한다. B의 판정 대상은 각 지표의 동일 시드 평균이 실제 진행에서도 구매 단계에 따라 증가하는지다.

전환별 96개는 여섯 프로필 × 16개 시점 지표다. 전체 **480개 중 208개가 감소**했다. 같은 가격인 분산 대 세트 비교를 빼도 더 산 경우 **384개 중 169개가 감소**해 단조성에 미달했다. 예를 들어 무광고 1→2세트의 28일차 현재 레벨 평균은 **−26.90**(95% 구간 −46.43~−7.33)이다. 같은 시드 10에서 1세트는 28일차 Lv89였고, 2세트는 27.34일 Lv87 동기화와 27.51일 Lv28 초기화 직후여서 Lv1이었다. 최고 레벨도 각각 Lv90과 Lv87이었다. 분기 시점이 현재 레벨과 회차 P를 크게 움직인다.

수정안은 시뮬 플레이어의 환생 판단에 회복 시간을 넣는 것이다. 최근 두 세션의 수입률로 현재 목표 도달과 환생 후 회복을 추정하고, 환생 경로가 적어도 한 세션 먼저 도달할 때 선택하는 정책을 대조한다. 같은 시드에 고정 환생 일정도 별도로 재생해 구매량 차이와 자동 의사결정 차이를 구분한다. 기존 목표 구간과 B 검사는 새로운 정책의 미보유 조건부터 다시 판정한다. 순차 구매의 결과는 D에서 같은 가격의 첫날 풀세트와 비교했다. [단계별 짝 통계](ex-precheck-tables/monotonicity.csv)

## C. 발동률과 실제 지급

정상 스와이프는 진행 중 성공한 스와이프를 전부 센다. 자동은 진행을 담당하는 정상 스와이프 64회마다 직전 상태와 시각을 복제해 `Engine.autoTarget`과 `Actor.Auto`로 실제 별도 정산한 표본이다. 자동 결과 분기는 진행 본체에 합류시키지 않는다. 같은 정상 플레이 상태를 기준으로 두 경로를 비교하므로 자동 전용 장시간 플레이 분포는 별도 모델의 대상이다.

## D. 체감 가치와 수입 외 대안

대안은 세트당 스와이프 상시 가산을 75bp에서 40bp로 줄이고, 세트당 오프라인 정산 시간 상한을 0.20% 늘린다. 전체 기준 상한 시간 +0.60%, 스와이프 가산 최대 +8.95%여서 연속량 기준 곱의 상한은 +9.6037%다. 기본 시간 상한 최솟값 8시간에서 정산 분 단위 내림 여유 1분을 더해도 이론 조합은 +10% 이내다. 정수 P 내림과 Lv 상한은 기존 것과 동일하다. 슬롯·에너지·플레이 속도와 구매 가격은 원안과 같은 설정에서 비교한다.

## 고정 시드 도전의 프리미엄 ★

도전 시작 시 `Meta.startChallenge`는 참가 계정의 키를 차감하고, `challengeBoard`는 별도의 `Engine.newGame` 상태를 만든다. 도전 상태의 `Account.premium`은 비어 있다. UTC epoch day 20000–20006의 7개 보드를 60초씩 실제 정산했을 때, 전 앱 ★5 계정과 ★가 없는 계정의 최종 점수는 모두 같았다. 양성 대조군으로 보드에 ★를 직접 넣었을 때는 해당 앱의 정산 P가 증가했다.

## 사용자 결정 요청

1. **아이템 조건** — C의 권고대로 프리즘 3종 유지, `reboot_frame`은 해금 후 상시 표기, 나머지 5개는 조건 변경으로 검토할지 결정한다. 다른 처리가 필요한 SKU는 유지 / 상시 / 변경 중 선택한다.
