m·o는 42일 안에 동기화한 시드가 모두 0/8이었다. 현재 `syncLevel`은 입장 레벨과 GB 환산 기준을 함께 높인다. 다음 검증은 자격 시점과 GB 지급 기준을 독립적으로 조정할 필요가 있다. n은 무과금 28일 4연쇄 이상이 1.32%에서 1.49%로 올라갔고 목표 8~15%에 못 미쳤다. 실측상 단순 확률을 더 올리는 것보다 깊은 연쇄를 만들 수 있는 보충 배치부터 조정할 근거가 있다.

p는 GB의 환산 기준을 Lv60에 고정해 진입 Lv75와 분리했다. 첫 동기화에 도달한 7개 시드의 중앙값은 34.18일, 28~42일 구간은 6/8, 미도달은 1/8이었다. q의 84일 오프라인 몫은 60.43%에서 55.96%로 줄었다. 첫 초기화는 2.01일로 늦어졌고 마지막 앱은 63.59일이어서 두 출시 목표를 함께 달성하지 못했다.

## 4. 화면 세션 전달

### VFX와 복귀 카드

- `burst.row.region`은 권역 ID, `burst.tierMax`는 해당 스와이프 직접 폭발의 최고 티어다. `burst.synergy`는 가장 큰 구성 시너지, `burst.effect`는 발동한 고유 효과 앱 ID다. `wave.waveIndex`는 1부터 시작하는 파동 번호다. [API와 예시](api-changes.md)
- 자동 정리 간격의 하한은 500ms다. 활성 자동 정리 수입 계수는 `autoIncomePermille: 600`으로 표시할 수 있다. 상태의 `overloadReadyInMs`가 양수라면 게이지가 100이어도 다음 파동까지 대기 시간이 남는다. 게이지·파동 연출에 이 값을 사용한다.
- 복귀 응답은 `awayMs`, `offlineCapMs`, `baseOfflineCapMs`, `basePaidShort`를 제공한다. 규칙 B 출시판의 EX 인정 시간과 추가 P는 0이다. Chromium 15시간 복귀에서 12시간 인정, 3시간 초과, 패스 +70% 행, 정산과 화면 금액 일치를 확인했다. [응답·표시 검증](launch-v1-data/return-15h.json)
- 화면 플랫폼의 확인된 광고 콜백을 `ad-` 지급 ID와 연결한다. 현재 복귀 버튼은 SDK 호출과 토스트까지 연결돼 있다. `OfflineDouble`의 당일 복귀 제안과 다음날까지 적용되는 보너스는 두 효과다. 플랫폼이 사용자가 선택한 효과와 지급을 일치시켜야 한다.

## 5. 검증과 남은 위험

- 코어 회귀 테스트는 88개를 통과했다. 강화 견적 계산 전후의 14일 자료, 자동 정리 60% 후보와 운영 기본값의 84일·8시드 `seeds.csv` 및 `ad-slots.csv`가 각각 바이트 단위로 일치했다.
- Chromium 복귀 카드, 효과 문구 생성 빌드, Android 디버그 APK의 조립과 lint를 확인했다. Android 패키지는 `io.github.graviton94.donotdisturb`다. GitHub Actions 실행 조회는 이 환경의 GitHub API 요청이 HTTP 403을 반환해 확인할 수 없었다.
- 11티어 AI 팩은 출시 84일 시점에 열어 이후 56일간 실행했다. 2/2가 마지막 앱을 구매했고 도구의 p50은 팩 적용 후 2일이었다. Lv147에 도달했으며 업데이트 뒤 추가 동기화는 없었다. [업데이트 실행 원본](launch-v1-data/ai-tier.txt)
- 출시 판정은 보류한다. 5→6티어와 첫 동기화 간격, 4연쇄와 중반 지갑 단위 기록을 우선 조정한다. 동기화 진입과 GB 환산 기준을 따로 바꿔 비교해야 Lv70과 Lv75 사이에서 지급 자체가 멈추는 원인을 분리할 수 있다.
- 가격·SKU·고유 효과의 승인된 의미는 원화 철회나 상품 교체 없이 유지했다. 제작 규칙·타깃 변경을 승인받아야 하는 경우에는 근거와 후보를 별도 비교한다. 현행 레벨 조회표 끝은 Lv400이므로, 이 84일 검증을 별도 무한 강화·EX 운영 이식 검수에 사용하지 않는다.
