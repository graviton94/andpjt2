이 보고서는 이전 Lv124 중심 검증의 원본이다. 사용자 방향 정정 이후의 기준과 결과는 [무한 증분·환생 가속과 유료 EX 재검증](GROWTH-LOOP-REPORT.md)에 있다.

## 코어가 연결된 범위

- `IntegratedGrowth`는 회차 레벨이 필요할 때 임계값을 연장한다. 파일·GB의 취득, 구매, 할인, 축적과 보존을 큰 정수로 연결했다. 텍스트 저장의 버전 1 숫자를 버전 2 정수 문자열로 올리는 이전 경로와 ValueCap 환급을 검증했다.
- EX 소유권은 거래 번호 중복 방지로 지급한다. 시뮬에서는 기존의 고정 보유·순차 보유 시나리오를 재현하기 위해 같은 9종을 시나리오가 투영한다. 실제 구매의 영수증 중복·재실행은 별도의 코어 고정 상태로 검증했다.
- 오프라인 수입률은 같은 스와이프 기록에서 EX 가산 전후를 따로 적립한다. 기본 정산과 시간 연장을 같은 광고·패스·울트라 상태에서 평가하고, 오프라인 부재 상한을 넘은 부분에는 오버클럭 시간을 추가하지 않는다.
- 도전은 참가 시점의 ★ 합만 보관한다. 도중 보유량이 바뀌어도 판 종료 점수의 배율은 참가 시점 기준이다. 도전용 계정과 공용 보드에는 EX 소유권과 ★의 앱 가치 배율이 들어가지 않는다.

현재 운영 코어는 공용 보드를 새 세션에서 만들고 `board.runEarned` 그대로 도전 점수와 개인 기록을 계산한다. 후보는 같은 원점수에서 ★ 1·15·30개에 각각 +0.10%·+1.50%·+3.00%를 추가한다. 기록은 원점수와 ★ 포함 기록을 따로 표시하는 안이다. 참가권 수·원점수·무료 조각 판정은 그대로 비교할 수 있다. ### 가격·지급 재검증 식

| 검증 기준 | 후보 수식과 확인 범위 |
|---|---|
| 회차 Lv | `P₂ = 30`, `Pₗ = 30 × ∏(j=2..l−1) [(2330 + 5 × max(0, j−24))/1000]`. 각 레벨에서만 정수부를 취한다. 지수형 구간에서 수입 +10%의 정적 환산은 Lv25 전후 약 0.113레벨, Lv124 약 0.092레벨이다. 실제 플레이의 P 지갑·환생 시점·도달일은 별도로 측정한다. |
| 강화 가격 | 현재 Lv가 `n`이면 백업 가치 `ceil(3 × 1.45ⁿ)` 파일, 백업 정산 시간 `ceil(4 × 1.50ⁿ)` 파일, GB 정산 시간 `3 × 2ⁿ` GB, 동기화 가치 `ceil(2 × 2.60ⁿ)` GB다. 할인은 가격 계산 뒤 적용한다. 일반 앱 강화는 앱별 기준 가격에 `1.30^(n−1)`을 곱한다. 구매 Lv에는 이전 상품 상한을 없앴고 정수 표현과 연산량의 한계는 남는다. |
| 환생 재원 | 리셋 기준 P 대비 비율 `x`의 파일 곡선은 `⌊10 × x^0.4⌋`에서 `x=10⁸` 이후 연속인 `⌊10 × (10⁸ × x)^0.2⌋`로 이어진다. 압축·누적 GB 보너스를 더한 뒤 회차 최고치 초과분을 지급한다. GB는 누적 파일 기준의 제곱근 곡선에서 이전 지급 기준치 초과분을 지급한다. |
| 시간·수입 | `인정 시간 = min(부재, 레벨별 8/10/12시간 + 백업 Lv시간 + GB Lv시간 + EX분)`. EX 계정의 오프라인 최종 지급은 `min(확장 지급, ⌊EX 전 동일 상태 지급 × 1.10⌋, 회차 방 한도)`다. 백업 정산률 증가분은 처음 10단계에서 +2%p씩, 이후에는 시간만 증가한다. |
| 구매 효용 | 개별 스와이프에서 `P_EX = min(R, ⌊P(10000+b)/10000⌋) − min(R,P)`를 가격·시간 대조와 독립적으로 확인한다. 같은 스와이프의 지급은 보유 수에 단조다. 회차 선택이 달라지는 완주 경로의 단조성은 별도 B 기준으로 검증한다. |

GB 동기화 가치 Lv30→31 가격은 약 5.63조 GB, Lv37→38 가격은 약 4,519조 GB다. GB 오프라인 시간 Lv51→52에는 약 6,755조 GB가 필요하다. 따라서 168일에 확인한 장기 구매 이후에도 같은 속도로 강화할 수 있다고 추정할 수 없다. 168일차 울트라 시드의 누적 GB는 약 2.07~2.36경이고, 대조에서 재시작한 메모는 두 시드 모두 20스와이프 뒤 Lv134였다. [장기 체크포인트](ex-integrated-checks/long-168/growth.csv)

장기 곡선의 다른 배율을 고정하면 총 파일은 회차 P의 약 0.2제곱, 총 GB는 약 0.1제곱에 비례한다. 동기화 가치 한 단계의 알림 ×2만으로 총 GB는 약 ×1.07이다. 다음 단계 가격은 ×2.6이다. 환생 기록·압축·상위 회차·저티어 재투자가 함께 커져야 장기 구매력이 이어진다. 현재 원자료는 168일까지 확인한 구매력과 Lv1001에서 한 번 구매한 증거다. 반복 구매 간격을 장기 출시 기준으로 삼을 때는 각 강화의 가격 대비 다음 환생 순수입을 추가로 검증한다.

장기 후보의 수치 반복 강화는 백업 가치·시작 자금·오프라인 시간·연쇄·마일스톤과 GB 압축·동기화 가치·오프라인 시간·연쇄·AI 가속이다. 슬롯 수, 확률, 자동 간격, 배터리 같은 한정 효과는 각 동작 한도에 맞춘다. 2단계 환생의 구매 루프에서 AI 콘텐츠는 비활성 상태로 실행했다. 후보는 랭크에 `Int`를 쓰며, 연쇄 배율의 일부 중간 계산도 `Int` 범위를 쓴다. 검증 범위를 크게 넘어서는 랭크는 덧셈 자료형과 큰 정수 연산 시간을 별도로 확인해야 한다. ### Lv124 이후 확장 대조

백업·GB 상점과 파일 지급의 기존 상한을 첫 Lv124 이전에 적용하고, 도달 후 새 성장에 연결하는 대조를 따로 실행했다. 무료·광고·패스·화면 보상형 패스·터보·울트라의 EX 미보유 10시드씩 총 60개다. 같은 시드의 이전 도달일은 59개가 정확히 같았고, 울트라 시드 6의 차이는 24초였다. 구간 안팎·미도달 판정은 60개 모두 같았다.

| 프로필 | 확장 전 Lv124 중앙값 | 목표 안 |
|---|---:|---:|
| 무광고 | 75.42일 | 9/10 |
| 광고 | 56.09일 | 10/10 |
| 월간 패스 | 43.58일 | 10/10 |
| 월간 패스 · 화면 보상만 | 47.00일 | 8/10 |
| 터보 | 27.17일 | 10/10 |
| 울트라 | 16.17일 | 8/10 |

별도 시드 7에서 풀세트 추가는 이 확장 대조의 광고 **54.00→56.17일**, 화면 보상형 패스 **40.00→46.01일**, 울트라 **17.17→15.00일**을 기록했다. 확장을 여는 시점은 EX 미보유의 진행 보존에 효과가 있다. 유료 효과와 경로 단조성은 추가 후보의 독립 검증 항목이다. [10시드 미보유](ex-integrated-checks/phase-ten/summary.csv) · [시드 7 풀세트 대조](ex-integrated-checks/phase-seed7/summary.csv)

확장 시점의 우선 대조안으로 이 방식을 권한다. 화면 보상형 패스는 10개 부분집합에서는 8/10이지만 기준 모델 30시드에서는 22/30이다. 공개 시점만 조정해 출시 기준을 충족할 수 있는지는 최소 30시드로 다시 판정해야 한다.

Lv100 이상에서 첫 Lv124까지 환생을 건너뛰는 시뮬 플레이어 대조도 했다. 같은 시드 7에서 광고 미보유는 54→76일, 풀세트는 56.17일→84일 한도에 Lv123이었다. 화면 보상형 패스는 미보유가 40→62일, 풀세트가 46.01→66일이었다. 이 회피 규칙은 테스트 목적으로만 썼다. 환생 정책을 바꿀 때는 직전 세션의 수입으로 새 판 회복 비용과 현재 판의 도달 시간을 직접 비교하고, 기존 규칙과 미보유 진도를 동시에 검증하는 쪽을 제안한다. [Lv100 보호 대조](ex-integrated-checks/protected-seed7/summary.csv) · [시드 7 환생 추적](ex-integrated-checks/protected-seed7/prestige.csv)

## 운영 경계와 화면 계약

현재 코어 **77개**, 격리 후보 **79개** 회귀가 모두 통과했다. 후보의 추가 두 검증은 기존 상한을 지난 오프라인 구매와 메모 Lv599→600 마일스톤이다. 기존 `files`와 `price` 숫자 필드는 JS 안전 범위 안에서 유지하고, 정확한 값은 `filesExact`, `priceExact`, `backupFilesNowExact`에 10진 문자열로 넘기는 후보를 검증했다.

운영 화면을 연결할 때 다음 계약이 필요하다.

| 화면 | 다음 연동에 필요한 필드 |
|---|---|
| EX 상점 `bm()` | SKU·가격·보유·발동 설명·세트 진척·구매 후 상시/최대 bp |
| 상태 스냅샷 | 현재 상시 bp, 회차 EX 추가 P 누적, 기본/EX 오프라인 상한, 두 강화 Lv |
| 복귀 정산과 스와이프 | 실제 부재·인정 시간, 실제 EX 추가 P의 10진 문자열, 발동 목록, 추가 P 0인 경우 `level_cap` 또는 정수 내림 사유 |
| 고정 시드 도전 | 원점수, 시작 시 ★ bp, 추가점수, 보정점수와 원점수 기록 |

격리 시뮬에서 쓰는 보유 시나리오와 운영 계정의 보유 세트·리부트 타이머를 연결하는 작업은 운영 전환 범위다. Android CI의 구매 확인→구매→정산→강제 종료→복원에서는 각 단계의 화면, API, 저장을 보존한다. M6는 Play의 비소모성 9종을 재설치·기기 변경 시 복원하고, 환불·회수된 상품과 세트 가산을 재계산하는 단계다. [코어 테스트 집계](ex-integrated-checks/core-test-suites.csv) · [기존 API 계약](api-changes.md)

## E. 재현과 원자료 무결성

30시드 실행은 84일 한도, 하루 4회 × 15분, 6프로필, 8구성이다. 합계 1,440개다. 7·14·28·56일차 마지막 세션의 환생 판단 후 상태를 기록하며 Lv124 도달일은 처음 도달한 시점이다. 시드가 84일 안에 도달하지 못하면 84일 수준으로 제한된 일수 통계와 양쪽 실제 도달 짝 통계를 함께 사용한다. 같은 시드 차이에서 4,000회 재표집해 평균·중앙값의 95% 구간을 구한다. 후보의 정수 환생 산식은 현재 기본 지수 400·500·850‰를 사용한다. 다른 지수로 사용자 값을 조정하려면 해당 정수 산식과 동등성 검증이 추가로 필요하다.

구성은 EX 0·1·3분산·3개 1세트·6개 2세트·9개 3세트, 3/14일차 순차 구매, 비교용 세트 P 40bp다. 시간 강화는 모든 구성의 통합 기본안에 있다. 마지막 비교군은 같은 시간 규칙에서 세트의 상시 P만 75→40bp로 줄인다. 일반 스와이프 64회마다 직전 상태·시간에서 자동 대상과 지급을 한 번 조사하고 진행에는 원래 일반 스와이프 결과를 사용한다. 자동의 집계는 실제 보드 상태를 사용한 조건 표본이며 자동 중심 플레이어의 완주 경로는 별도로 검증할 수 있다.

```sh
python3 tools/economy-sim/ex-precheck.py /tmp/integrated-30 --integrated --seeds 30 \
  --cases none,full,one,one_set,spread_three,two_sets,staged,offline_cap
python3 tools/economy-sim/precheck/analyze.py /tmp/integrated-30 /tmp/integrated-tables
python3 tools/economy-sim/ex-precheck.py /tmp/integrated-fixtures --integrated --audit-only
python3 tools/economy-sim/ex-precheck.py /tmp/integrated-long --integrated --days 168 \
  --profiles Free,Spend30,Spend100 --cases none --seeds 2
```

위 실행은 기준 커밋의 깨끗한 체크아웃에서 한다. 원본 Actions는 60개 중 56개 묶음을 만들었다. Gradle 단계에서 실패한 4묶음은 같은 리비전·Kotlin 소스·시드로 다시 실행했고, 복구 워크플로가 전체 1,440개를 병합했다. 병합 결과는 도달 요약 1,440행, 시점 5,760행, 환생 171,703행, 조건 19,440행, 지급 표본 2,160행이다. 다섯 표의 SHA-256, 기본·격리 코어의 소스와 재실행 증거를 아래 자료에서 확인할 수 있다. [원본 분산 실행](https://github.com/graviton94/donotdisturb/actions/runs/45603785627) · [복구와 원자료 게시](https://github.com/graviton94/donotdisturb/actions/runs/45605456907) · [소스·원자료 매니페스트](ex-integrated-data/manifest.json)

복구된 4묶음의 96경로를 로컬 격리 코어에서 별도로 재생했다. Actions 결과에 대응하는 다섯 CSV의 행이 바이트 단위로 일치했다. 자연 168일 실행의 첫 56일 체크포인트 24개 행도 84일 실행과 일치했다. 두 분석 명령을 새 폴더에서 다시 실행했을 때 14개 통계 CSV가 모두 동일했다. [로컬과 Actions 재생 비교](ex-integrated-checks/reproduction.csv)

## 검토 후 사용자 결정

| 결정 | 확인할 내용 |
|---|---|
| EX 조건 +0.25%p | 각 SKU의 조건 유지, 해금 후 상시 표기, 조건 변경을 발동 실측과 함께 결정한다. |
| 세트 수입과 시간 | 세트의 75bp를 유지할지, 40bp와 앞당긴 시간 확장을 후속 검증할지 결정한다. 기본 강화 +1시간/Lv는 확정 사항이다. |
| 무한 성장 공개 시점 | 첫 Lv124 이후 단계적으로 열거나 초반 성장 규칙을 재조정할지 결정한다. 후자의 경우 기존 Lv124 목표도 같은 시드에서 맞춘다. |
| 도전의 ★ | 시작 시 보유 ★당 10bp·최대 300bp와 원점수/보정점수 분리 제안을 확정할지 결정한다. |
| 이전 저장과 환급 | `ValueCap`을 이전할 때 실제 매입 GB를 한 번 반환하는 방식을 확정할지 결정한다. |
| 운영 구현 착수 | A·B 성능 기준을 해결한 뒤 운영 이식, 화면 계약, 기기 검수의 착수를 승인할지 결정한다. |

위 항목에 대한 독립 리뷰와 착수 승인 여부는 복사용 요청서에 정리했다. [다른 세션용 검토 요청서](integrated-review-prompt.md)
