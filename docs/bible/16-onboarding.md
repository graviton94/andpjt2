# 16 · 튜토리얼 · 첫 경험 대본

첫 10초부터 첫 공장 초기화(Lv25, 평균 1.5~2일)까지. 목표 지표(마스터 플랜 7단계): 신규 10명 중 8명이 10초 안에 첫 폭발, D1 ≥ 40%, 첫 초기화 완료율 ≥ 35%.

## 1. 원칙

| 원칙 | 기준 |
|---|---|
| 한 번에 하나 | 비트마다 새 것은 하나. 설명보다 손이 먼저 |
| 글은 한 줄 | 안내 문구 18자 안팎, 최대 2줄. 문단 금지 |
| 막지 않는다 | 강제 대기 5초 이하. 모든 안내는 건너뛰기 가능, 설정에서 다시 보기 |
| 손가락 커서 | 처음 3번의 스와이프는 손가락 애니메이션이 대상 줄을 가리킨다. 4번째부터는 7초 멈추면 힌트 |
| 실패 없음 | 어떤 줄을 밀어도 손해 없다(결정 기록 "실패 없음") |
| 시스템 UI와 구분 | 안내는 게임 고유 말풍선(실제 OS 토스트·알림 모양 금지) |

## 3. 첫 판 사양 (엔진 고정)

`Engine.newGame`의 고정 배치: 시계1 · 날씨2 · 메모2 · **날씨1** · 메모2 · 시계1 · 날씨2. 4번째 줄(날씨1)을 밀면 위아래 메모2+2가 붙어 4개 폭발 → 연쇄 1. 테스트 `firstSwipeIsOneSmallBurst`가 이 결과를 고정한다.

## 4. 문구 규칙 (UX 카피)

- 말투: 친근한 해요체, 주어 생략, 명령보다 결과("밀어서 지워요").
- 숫자는 연출로 보여 주고 문구에는 넣지 않는다(예외: 오프라인 정산·초기화 미리보기).
- 실제 OS 표현 금지: "시스템", "경고", "보안" 같은 단어로 실제 기기 알림을 흉내 내지 않는다.

## 5. 측정 (소프트런치)

깔때기: `ftue_start → first_burst → first_buy → deck → first_reset`. 단계별 이탈이 15%를 넘는 지점부터 문구·타이밍을 고친다.
