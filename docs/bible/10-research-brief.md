# 10 · 추가 사례조사 발주서 (프롬프트)

첫 보고서(09번 문서)는 8×8 색 블록 게임 기준이라 우리 구조와 맞지 않는 부분이 있었다. 아래는 **우리 게임에 맞춘 2차 조사**를 맡길 때 그대로 붙여 넣는 프롬프트다. 한 번에 전부 맡기기보다 A~F를 묶음별로 나눠 발주하면 깊이가 나온다. 각 묶음은 독립적으로 쓸 수 있게 맥락을 반복해 둔다.

---

## 공통 맥락 (모든 묶음 앞에 붙임)

```text
당신은 모바일 F2P 게임 경제·라이브옵스 리서처다. 아래 게임을 위한 조사 보고서를 한국어로 작성한다.

[게임 개요]
- 플랫폼: Android 우선(국내 출시 → 글로벌), 세로 화면, 한 손 조작. 1인 개발 스튜디오.
- 장르: 방치형(인크리멘탈) + 연쇄 퍼즐 + 덱 구성 + 환생(프레스티지). 무료, 보상형 광고 + 인앱결제.
- 판타지: 화면 전체가 안드로이드 시스템 UI처럼 보인다. 위쪽 상태표시줄이 게임 HUD(배터리=행동력,
  신호=과부하 게이지), 위에서 끌어내리면 빠른 설정 패널이 상점·강화·설정. 게임판은 잠금화면 알림 목록.
- 코어 규칙: 세로 7~12줄 알림 목록에서 한 줄을 옆으로 밀어 지운다. 위아래가 같은 앱이면 합쳐지고
  수량이 4 이상이면 폭발, 다시 위아래를 확인해 연쇄. 연쇄 번호마다 배율 ×(1+n). 과부하 게이지가 차면
  폭발한 앱의 숨은 대기 알림이 파동으로 터진다(파동마다 ×3).
- 성장: 가상 앱 24종(6티어, 티어마다 알림 가치 ×10)을 P(재화)로 사서 "덱"(동시에 알림을 보내는 앱
  3~10개, 레벨로 최소·최대가 오름)에 넣는다. 덱 안의 같은 권역·카테고리 수로 시너지(+20~300%).
  앱 강화(가치 ∝ 레벨, 10·25·50…단계마다 ×2), 앱 프로 버전(×3), 이벤트 카드(별도 슬롯),
  판 강화(과부하 깊이·샌드위치 확률·판 길이·와일드).
- 레벨: 이번 회차 누적 P의 지수 함수(레벨마다 필요 P ×2.5 이상). 해금 전용, 가치에 곱하지 않음.
- 환생: Lv25부터 "공장 초기화". 레벨·앱·강화·P·카드가 초기화되고 백업파일을 받는다
  (⌊10×∛(P/10¹²)⌋ + (레벨−20)). 평생 얻은 백업파일 1개당 모든 가치 +5%. 백업 상점 16항목.
  2차 환생 "클라우드 동기화" 계획.
- 목표 페이싱: 하루 직접 플레이 1시간 + 오프라인. 첫 초기화 1일차, 5티어 1주, 6티어 3~4주,
  마지막 앱 6~8주. 환생 없이는 한 달 넘게 해도 마지막 앱이 어려움. 해금은 레벨마다 하나 이상.
- 현재 시뮬레이터 결과: 직접 플레이가 자동 대비 2.1~3.0배 효율, 2주차에 환생 효과로 급성장 후 둔화.

[작성 원칙]
- 모든 수치에 출처(URL, 발행일, 표본)를 붙인다. 추정은 "추정"이라고 쓰고 근거를 적는다.
- 공식은 변수 정의와 함께, 표는 우리 게임 변수 이름으로 다시 매핑해서 쓴다.
- 마지막 장에 "이 게임에 바로 적용할 권고 10개"를 우선순위·예상 효과·위험과 함께 적는다.
- 확인되지 않은 수치를 만들어 내지 않는다. 공개 자료가 없으면 "공개 자료 없음"이라고 쓴다.
```

## 묶음 A · 장기 페이싱과 다층 환생 (가장 시급)

```text
[조사 질문]
1. 출시 후 1~6개월 장기 플레이를 설계한 방치형·인크리멘탈 게임 10종 이상에서, 1차·2차·3차 환생 계층이
   각각 플레이 몇 일차에 처음 도달되도록 설계되었는지 (공개 위키·개발자 발언·커뮤니티 타임라인).
   대상 예: Antimatter Dimensions, Idle Brick Breaker, Realm Grinder, Egg Inc., Cookie Clicker,
   AdVenture Capitalist/Communist, Tap Titans 2, Clicker Heroes 1/2, NGU Idle, Melvor Idle, Legend of Slime.
2. 각 게임의 1차 환생 재화 공식(곡률), 영구 보너스 구조(재화당 %, 소프트캡), 회차 길이 변화
   (Run 1, 5, 10, 20, 50의 소요 시간)를 표로.
3. "환생할수록 회차가 짧아지다가 다시 길어지는" 패턴을 만드는 장치(소프트캡, 2차 환생 해금 조건,
   챌린지)를 유형별로 정리.
4. 해금 밀도: 첫 1일·1주·1개월 동안 새 기능/콘텐츠가 몇 분·몇 시간 간격으로 열리는지
   (가능한 게임만, 타임라인 근거 필수).
[산출물] 게임별 비교표, 회차 길이 곡선 비교, 우리 목표(첫 초기화 1일, 마지막 앱 6~8주)에 맞는
환생 공식·2차 환생 조건 3안과 각각의 예상 회차 곡선.
```

## 묶음 B · 덱·슬롯 제약이 있는 방치형/로그라이트의 빌드 다양성

```text
[조사 질문]
1. 장착 슬롯(덱) 수를 제한하고 레벨·진행에 따라 늘리는 게임에서, 슬롯 최소 사용 강제나 "적게 넣을수록
   유리한 꼼수"를 막는 설계 사례 (Balatro 조커 슬롯, Slay the Spire 덱 압축 대응, Vampire Survivors
   무기 슬롯, Backpack Hero, Luck be a Landlord, Dicey Dungeons, 방치형 RPG의 장비·동료 슬롯).
2. 세트/시너지 보너스(같은 계열 n개 장착 시)의 단계 수치 사례와, 시너지가 "최적 덱 하나로 수렴"하지
   않게 만드는 방법(상호 배타 시너지, 회차별 무작위 보너스, 로테이션).
3. 저등급 아이템이 후반에도 쓰이게 하는 장치(점화제·촉매 역할, 강화 비용 차등, 세트 구성 재료) 사례.
[산출물] 패턴 카탈로그(이름·작동 원리·수치 예·우리 게임 적용안), 시너지 단계표 3안.
```

## 묶음 C · 알림/OS UI 판타지와 IP·스토어 정책

```text
[조사 질문]
1. 운영체제 UI(알림창, 홈 화면, 메신저, 데스크톱)를 게임 판타지로 쓴 게임 사례와 흥행·리뷰 반응
   (예: Hypnospace Outlaw, Emily is Away, Simulacra, Replica, A Normal Lost Phone, 국내 사례 포함).
2. 실제 OS·제조사 UI(Android, One UI, iOS)와 "비슷해 보이는" 디자인의 상표·트레이드 드레스 위험,
   Google Play 정책(시스템 알림 사칭, 기만적 UI 금지) 조항 원문과 실제 거절 사례.
3. 가상 앱 이름·아이콘이 실제 서비스(카카오톡, 쿠팡, 배민 등)를 연상시킬 때의 위험 수준과 안전한 작명 기준.
[산출물] 위험도 표(높음/중간/낮음), 우리 UI·앱 이름 체크리스트, 스토어 등록 문구 주의사항.
```

## 묶음 D · 국내 Android 수익화·리텐션·규제 (2025~2026)

```text
[조사 질문]
1. 한국 Google Play 기준 방치형·캐주얼 퍼즐의 D1/D7/D30 리텐션, ARPDAU, 결제 전환율, 보상형 광고
   eCPM(한국 트래픽) 최신 수치와 출처.
2. 보상형 광고 "2배 보상"의 일일 상한, 시청 횟수 분포, 매출 잠식 사례.
3. 국내 확률형 아이템 정보 공개 의무(게임산업진흥법 개정, 2024.3 시행) 적용 범위: 꾸미기 뽑기,
   유물 가챠, 천장 표기 방법. 청소년 결제·환불 규정, 개인정보(광고 ID) 고지 요건.
4. 1인·소규모 스튜디오의 단계적 수익화 출시 사례(광고만 → 광고 제거 → 패스)와 KPI 게이트.
[산출물] 벤치마크 표, 규제 체크리스트, 우리 게임 수익화 롤아웃 일정안(출시 0~12주).
```

## 묶음 E · 오프라인 정산·자동화·시간 조작 방어

```text
[조사 질문]
1. 방치형 게임의 오프라인 보상 공식(효율 계수, 상한 시간, 복귀 팝업 배수)을 게임별로 비교.
   효율 기준이 "액티브 속도"인지 "자동 속도"인지 구분해서.
2. 자동화(오토바이어, 자동 환생, 자동 덱 편성)를 언제·어떤 비용으로 여는지와 그 뒤 리텐션 변화.
3. Android에서 기기 시계 조작·백그라운드 종료·재설치를 이용한 부정 사례와 방어(단조 시계, 서버 시간,
   Play Integrity) 구현 사례.
[산출물] 공식 비교표, 자동화 해금 타이밍 권고, 방어 설계 체크리스트.
```

## 묶음 F · 타격감·연출 (세로 리스트 퍼즐)

```text
[조사 질문]
1. 리스트·카드를 스와이프해 지우는 게임(메일 정리 게임, 틴더형 스와이프, 2048 계열)의 타격감 연출
   (히트스톱 ms, 셰이크 강도, 햅틱 패턴, 사운드 피치 상승) 공개 자료와 GDC 강연.
2. 큰 숫자 연출(카운트업 속도, 단위 전환 시점, 단계별 팝업)이 이해도와 만족도에 주는 영향.
3. Android 햅틱 API(VibrationEffect.Composition 등) 기기별 지원 차이와 대체 패턴.
[산출물] 연출 파라미터 표(우리 디자인 토큰 motion 항목에 바로 넣을 수 있는 값), 기기 대응표.
```

## 발주 순서 제안

1. **A**(장기 페이싱) — 경제 v0.4 튜닝의 기준이 된다.
2. **C**(OS UI·IP) — 출시 전 위험 제거, 디자인 정본과 직결.
3. **D**(국내 수익화·규제) — 6단계 전에.
4. B, E, F — 그레이박스·수직 슬라이스 단계에서.

받은 보고서는 09번 문서처럼 "채택 / 변형 / 보류" 매트릭스로 바이블에 반영한다.
