# 15 · 앱 고유 효과 (규칙 B)

앱 60종마다 효과 하나. **덱에 넣은 앱만 효과를 낸다.** 엔진 데이터는 `Content.kt`의 `Catalog.effects`, 구현은 `Engine`의 효과 훅.

## 1. 원칙

| 원칙 | 기준 |
|---|---|
| 강도 예산 | 자기 수입에 평균 **+20~40%**. 덱 전체에 거는 효과는 덱 수입 **+10~20%**. 도박형 기댓값 ≤ ×1.4 |
| 티어가 이긴다 | 어떤 효과도 티어 한 칸(×6)을 넘지 않는다. 효과는 덱을 짜는 이유이지 티어를 건너뛰는 수단이 아니다 |
| 겹치지 않게 | 60종이 12계열에 나뉘고, 같은 계열 안에서도 조건이 다르다 |
| 오프라인을 키우지 않는다 | 오프라인 몫이 이미 목표를 넘는다(58%). 오프라인 배율 효과는 "돌아온 뒤 직접 플레이 보너스"로 바꾼다 |
| 단계 구현 | 1차(경제 영향이 크거나 구현이 단순한 것)를 먼저 넣고 재측정, 2차(판 조작·상태 추적)는 수직 슬라이스 전에 |

**1차** = 엔진 반영, **2차** = 수직 슬라이스 전 → **2차 ✓ 13종 엔진 반영 완료(11-23)**: 날씨·음성 녹음·카메라·갤러리·듀오링구(출석 연속 일수)·코코아T(합칠 때 다른 택시 줄 끌어옴)·컵컷·쿠빵(한국 시각 22~7시 복귀)·라자다다·우바·틱특·와이·큐글맵스(다른 앱과도 합쳐짐). 확률은 상태 해시라 판 난수 순서를 바꾸지 않는다. 테스트 `phaseTwoEffectsWork`. ✎ = 이번에 바뀐 효과(겹침·오프라인 문제 해소).

## 4. 검증

- `CoreRulesTest`에서 효과 계열별 고정 판을 검증한다. 런타임 발동은 `WebSessionTest`에서 확인한다.
- 12주 시뮬레이션 재측정: 마지막 앱 도착, 오프라인 몫, 해금 공백. 효과 합계가 곡선을 앞당기면 해금 레벨 배치로 맞춘다(공식은 그대로).
- 시뮬레이터의 덱 선택은 효과를 반영한 기대 가치로 고른다.

## 5. 구현 결과

- 1차 45종 엔진 반영, 테스트 7개(가치·덱 한정·임계·경제·시간·방어·업데이트 항목). 무작위 효과(로빈훗훗·메이버)는 상태 해시로 굴려 효과 없는 덱의 판 순서를 바꾸지 않는다.
- 경제 영향: 마지막 앱이 11일 당겨짐(78 → 67일), 오프라인 몫 58 → 52%. 9·10티어 해금 레벨 이동으로 보정(04 경제 10장).
- 2차 15종(날씨·음성 녹음·카메라·갤러리·듀오링구·코코아T·컵컷·쿠빵·라자다다·우바·틱특·와이·큐글맵스·챗GTP 두 수 앞)은 수직 슬라이스 전.
