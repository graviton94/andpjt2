## 2. 4연쇄 목표 재정의
규칙 B에서는 두 줄만 닿아도 바로 터지므로 4연쇄 이상이 구조적으로 드물다(1.41%). 억지로 판 배치를 바꾸기 전에:
- 규칙 B에서 "큰 연쇄"를 만드는 실제 경로(위 줄이 떨어지며 다시 닿는 연쇄)를 계측해 분포를 보고하고,
- **목표를 근거와 함께 다시 제안**해라(예: 3연쇄 이상 x%, 9연쇄 이상 하루 n회). 연출 단계(2~3 / 4~5 / 6~8 / 9+)는 화면이 이미 이 구간으로 색을 바꾸니, 각 구간이 하루에 몇 번 보이는지가 손맛 지표다.
- 판 배치 변경이 필요하면 v1.0 손맛 지표(폭발률·파동 빈도)를 깨지 않는 범위에서.

## 3. 패스 가치를 화면에 (새 필드, **추가만**)
사용자 요청: 패스 가치표를 팝업이 아니라 **각 패스 구매 카드 바로 밑**에 보여 주고, 월간 패스는 첫 구매 상품처럼 **"최대 ×N 가치" 캡슐**로 강하게 홍보한다(월간 패스가 첫 구매를 대체하는 상시 상품). 화면이 계산하지 않도록 코어가 숫자를 준다:

`bm().passValues`: `{ "month": {...}, "Turbo": {...}, "Ultra": {...} }`, 각 항목
- `wonPrice` (원), `dataNow`, `dataDaily`, `days`, `overclockHoursDaily`, `adFree` (bool), `speedPermille`, `prestigePermille`
- `dataTotal` (30일 데이터 합), `dataEquivalent` (데이터+오버클럭 환산 합, 17장 기준)
- `valueX` (= 데이터 환산 ÷ 가격, 17장의 ₩22/데이터 기준, 소수 1자리) · `valueXDataOnly` (오버클럭 제외)
- 스타터·초심자에도 같은 `valueX`를 `starterValueX`, `rookieValueX`로(지금 화면 스티커 10.2× · 7.1×와 같은 기준인지 확인).

캡슐에 쓸 숫자("최대 ×N")는 `valueX`다. 사용자는 월간 패스를 약 9배로 인식하고 있다(데이터만 2,100 → 약 8.4×). 어느 쪽을 "최대 가치"로 표기할지 근거와 함께 보고서에 명시해(표시·광고 규정상 과장이 되지 않도록, 실제 30일 다 받았을 때 기준).

## 4. 광고 지급 ID
화면이 AdMob 보상 확인 뒤 `watchAd(slot, adId)`에 `ad-<기기 보상 고유값>`을 넘기도록 바꾼다(화면 세션 작업). 코어는 지금처럼 claim 1회만 지급하면 된다 — 변경 없음.
