## 2. 번역 규칙 (중요 — 지키면 번역이 안 깨진다)

화면은 이제 **기본 영어**, 한국어 기기에서만 한국어다. 코어가 보내는 한국어 라벨은 화면 쪽 사전(`tools/game-page/i18n/en.json`)이 그려지는 순간 번역한다. 사전 키는 **숫자·영문 토큰을 `#`로 바꾼 문장**이다.
- 예: `"알림 가치 ×1.25"` → 키 `"알림 가치 #"`. 그러니 **숫자만 바꾸는 건 자유**.
- **문장(한글 부분)을 새로 만들거나 바꾸면** 영어가 비어 한국어로 보인다 → 보고서 끝에 "새/바뀐 한국어 문구" 목록(키 형태 `#` 포함 + 뜻 설명)을 반드시 남겨라. 화면 세션이 영어를 붙인다.
- 앱 이름은 id로 영어 치환하므로 신경 쓰지 마. 새 앱을 추가하면 id·한국어 이름·카테고리·권역·티어를 목록에 적어라.
- `id` 값(앱 id, 아이템 id, 업적 id 등)은 **절대 바꾸지 마** — 번역·저장·결제가 id에 묶여 있다.

## 3. 과제 A — 규칙 B를 엔진에 이식 (필수, 먼저)

사용자 결정(11-26): **"같은 앱끼리 맞닿으면 바로 터진다" — 폭발 기준(threshold) 4 → 2.**
현재 `Rules.kt`의 `threshold = 4`. 화면 연출·문구는 이미 규칙 B 기준이다.

1. `threshold = 2` (기본값). 와일드·샌드위치·연쇄 번호·게이지 계산이 "4개 모이면"을 전제로 한 곳을 전부 찾아 규칙 B 의미로 고쳐라.
2. 규칙 B로 의미가 사라진 고유 효과 5종을 `app-effects.ko.json`의 새 문구대로 구현:
   | 앱 | 새 효과 (ko 원문) |
   |---|---|
   | calc 계산기 | 짝수 연쇄에서 터지면 → 그 폭발 +50% |
   | match 텐더 | 이 앱 두 줄이 맞닿으면 → 연쇄 번호 +2 (짝 맞추기 보너스) |
   | green 왓츠업 | 이 앱이 터질 때마다 → 과부하 게이지 +10 |
   | ride 우바 | 수량 4 이상으로 터지면 → 다음 자동 대기 −2초 |
   | ctaxi 코코아T | 이 앱 줄이 합쳐질 때 → 옆 같은 앱 줄도 함께 펑 |
   나머지 55종도 규칙 B에서 **문구와 동작이 일치하는지** 전수 확인. 어긋나면 동작을 문구에 맞추거나, 문구를 고치고 목록에 적어라.
3. `CoreRulesTest`·`WebSessionTest`·`Examples.kt`·`docs/core-rules-v3.md`의 고정 예시를 규칙 B로 갱신. `gradle -p core test` 녹색.
4. 규칙 B는 폭발 빈도를 크게 올린다 → 아래 과제 B의 재밸런싱이 필수다. A만 하고 멈추지 마.

## 4. 과제 B — 출시 기준 전면 재밸런싱 (길고 정교하게)

### B-1. 목표 (출시 기준선, 12주)

**진행 곡선** (무과금 기준, 시드 ≥ 8 중앙값, 84일 시뮬, 하루 4회 × 15분 + 오프라인):

| 지표 | 목표 |
|---|---|
| 첫 공장 초기화 | 1~2일 (36시간 이내가 이상적) |
| 5티어 첫 앱 / 6티어 첫 앱 | 약 7일 / 3~4주 |
| 마지막 앱(Lv124, 10티어) | 10~12주 (8/8 시드 모두 84일 안 도달) |
| 주별 최고 레벨 | 매주 상승, 정체 주 없음 |
| 환생 없이 30일 | Lv30~35 |
| 오프라인 몫 | 30~50% |
| 해금 달력 최대 공백 | 7일 이하(엔진 콘텐츠만으로 측정, 꾸미기·칭호 제외) |
| 클라우드 동기화(2차 환생) 첫 도달 | 4~6주 |

**BM 프로필별 마지막 앱 도달** (17장 3절 유지): 무과금 10~12주 · 광고 꾸준히 8주 · 월간 패스 6주 · 터보 4주 · 울트라 2주. 프로필 간 순서가 절대 뒤집히지 않을 것, 광고 시청자 가속 ≥ 1.25×.

**손맛(도파민) 지표 — 이번에 새로 측정해 기준을 세워라.** 규칙 B의 목적은 "자주 터지고 숫자가 계속 커지는 맛"이다. 시뮬에 아래 계측을 추가하고 목표를 제안·검증해:

| 지표 | 제안 목표 (근거와 함께 확정해) |
|---|---|
| 스와이프당 폭발 확률 | 초반(Lv1~10) ≥ 70%, 중반 이후 ≥ 55% |
| 연쇄 길이 분포 | 2연쇄 이상 30~40%, 4연쇄 이상 8~15%, 9연쇄 이상 하루 몇 번(0.5~2%) |
| 과부하 파동 빈도 | 15분 세션당 1~3회 |
| 한 방 최고 기록 갱신 빈도 | 첫 주 하루 5회 이상, 이후 세션당 1회 안팎 |
| 지갑 단위 상승(K→M→B→aa…) 간격 | 초반 수 분 단위, 중반 이후에도 세션마다 1번은 단위가 오르는 느낌 |
| 돌발·시간형 카드(알림훈련·행운 알림·배터리·앱 충돌·스팸 전화) | 세션당 1~2회, 같은 종류 연속 없음 |

### B-2. 방법

1. **손잡이 목록부터**: 규칙 B에서 의미가 바뀐 상수(합쳐짐당 게이지, 연쇄 배율, 와일드·샌드위치 확률, 줄 생성 분포, 스팸 비율, 자동 정리 간격, 레벨 곡선, 가격 성장률, 백업파일 공식, 오프라인 효율)를 표로 정리하고 각 손잡이가 어떤 지표를 움직이는지 적어라(04장 3절 갱신).
2. **한 번에 한 손잡이**: 판마다 바꾼 것 1~2개만, 시드 8 중앙값과 최악 시드를 함께 기록. 판 이름 v1.0a, v1.0b… 로 04장에 표로 남겨라.
3. **콘텐츠 배치로 먼저, 공식은 나중에**: 티어별 도착 시점은 해금 레벨·가격 배치로 맞추고, 레벨 곡선·백업 공식 같은 전역 공식은 마지막 수단.
4. **극단 점검**: 최적 플레이(항상 최선 스와이프), 무작위 스와이프, 자동 정리만(방치) 세 행동 모델에서 각각 목표 대비 위치를 보고하고, 방치가 손 플레이를 이기는 구간이 없게 해라(손으로 밀 이유 유지 — 메모 앱 "손으로 밀면 ×2" 등).
5. **한 방 상한·과열(overheat) 재검증**: 폭발 빈도가 오르면 한 방 상한에 자주 닿을 수 있다. 상한 도달 빈도와 "넘친 만큼 버림" 체감이 과하지 않은지 확인.
6. **스팸 악용 재검증**(13장 A-F 결론 유지): 규칙 B에서 스팸·와일드로 무한 연쇄를 만드는 경로가 없는지 시뮬·단위 테스트로 증명.
7. **업데이트 1(11티어 AI, 14장)** 도착 시점이 새 곡선에서도 성립하는지 재확인.

### B-3. BM 재검증 (17장)

- 규칙 B 후 광고 보상(부스트·오버클럭·시간 도약·오프라인 ×2·최고 기록 ×2·데이터 상자·무료 강화)의 체감 가치를 다시 계산하고, 하루 광고 한도와 쿨다운을 확정.
- 데이터 팩 6종·스타터·초심자·월간·터보·울트라 패스·프리미엄 ★·백업 부스트의 **가치표(데이터 환산)**를 갱신. "첫 구매 ×2" 등 표기와 실제 지급이 일치하는지 테스트.
- **결제 상품 ID 확정**: Play Billing용 상품 ID 목록을 `docs/bible/17-monetization.md`에 표로(형식 예: `dnd_data_1`, `dnd_pass_month`, `dnd_pass_turbo`, `dnd_pass_ultra`, `dnd_starter`, `dnd_beginner` — 소문자·숫자·밑줄), 일회성/구독 구분, 한국 가격(₩), 지급 내용. 화면 세션이 이걸로 Play Console 상품을 만든다.
- 금지 유지: **확률형(가챠) 유료 상품 없음**, 강제 광고 없음. P2W는 허용(게임 정체성).

### B-4. 화면 세션이 VFX에 쓸 데이터 (WebSession에 **추가만**)

화면 세션이 "앱 색·티어·권역·콤보 단계별로 더 화려한 연출"을 만든다. 아래 필드를 추가해 줘(이미 있는 건 유지):
- `burst.row.region` (앱 권역 id), `burst.synergy`: `{ "kind": "region"|"cat", "key": "...", "mult": n }` (그 폭발에 시너지가 붙었을 때만)
- `burst.effect`: 그 폭발에서 발동한 고유 효과 앱 id 배열(없으면 생략)
- `burst.tierMax`: 그 연쇄에 포함된 최고 티어
- 과부하 파동 비트에 `waveIndex`(몇 번째 파동)
- 새 돌발/이벤트를 만들면 비트 `t` 이름만 정하고 목록에 적어라 — 연출은 화면 세션이 붙인다.
