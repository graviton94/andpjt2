## 1. 버그 (최우선) — 같은 앱이 붙은 채 멈춰 있다
사용자 제보(실기기, 0.6.0): 판에 `시계 / 시계`가 붙어 있는데 터지지 않는다. 다음 스와이프에서도 터지지 않아 연쇄가 끊긴다.

화면 세션이 dev 서버로 재현했다. 시드 11~16에서 Lv7, 덱은 시계·날씨·메모, 스와이프·자동·오프라인을 무작위로 1,500회 섞었다.

| 엔진 | 쉬는 판에 붙은 같은 앱 쌍 |
|---|---|
| 0.6.0 (`4b45888`) | 188 / 1500 (12.5%) — 스와이프 106 · 자동 45 · 오프라인 37 |
| v1.2 (`e300da9`) | 4 / 1500 (0.27%) — 전부 `chainEnd` `wave`/`spam` 직후 |

재현 예시 (v1.2, 시드 11, 163번째):
- 비트 `swiped,merged,burst,spawn,spawn,merged,burst,wave,chainEnd,spawned×3` → 판 `alarm memo alarm weather weather alarm weather`
- 다음 스와이프 `swiped,spawned` → `weather weather`가 **그대로 남음**.

원인 추정: 규칙 B가 "이번 스와이프가 만든 접촉"만 본다. 브레이커로 끝난 뒤의 최종 보충(`spawned`)이나 그 전에 남은 쌍은 아무도 다시 검사하지 않는다.

요구:
1. **불변식**: 플레이어 입력을 기다리는 판(스와이프·자동·오프라인·로드 직후 모두)에는 붙은 같은 앱 쌍이 **0개**다. 와일드나 규칙상 합쳐지는 다른 조합도 같다.
2. 처리 방식은 네가 정하되 체감 근거를 보고해라.
   - 후보 A: 다음 스와이프 시작 때 남은 쌍부터 터뜨린다(연쇄 1부터).
   - 후보 B: 최종 보충이 쌍을 만들지 않게 뽑는다(스팸·파동이 끝낸 연쇄를 존중).
   - 브레이커가 "큰 한 방으로 끝났다"는 느낌을 해치지 않는 쪽을 골라라.
3. **0.6.0 저장 호환**: 이미 붙은 쌍이 저장된 판은 첫 로드나 첫 스와이프에서 정리되게 해라.
4. 테스트: 무작위 입력 시뮬(스와이프·자동·오프라인·이벤트 카드·알림 행 포함) 1만 회 이상에서 불변식 위반 0. 코어 테스트로 고정해라.
   - 화면 쪽 재현 스크립트 방식: 매 행동 뒤 `snapshot.rows`에서 이웃한 `kind=App`의 `app`이 같은지 검사.
